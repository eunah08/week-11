# 캐시 ON/OFF 실측

자동 생성: `python3 bench/compare.py`.

측정 시각: 2026-11-12T14:24:08.992122+00:00. OS: macOS-15.7.7-x86_64-i386-64bit-Mach-O.
CPU: Intel(R) Core(TM) i5-8259U CPU @ 2.30GHz, 논리 CPU 8개.

- 각 행은 60요청 × 3회. 동시 요청 수 4.
- 원본 지연 300ms, TTL 60000ms.
- 매 시나리오·모드·반복마다 두 프로세스를 새로 시작해 원본 수정·횟수·캐시를 초기화.
- 같은 상품 ID 순서. 무작위는 seed 42. ON/OFF 실행 순서를 반복마다 교대.
- 첫 1회는 빈 캐시에서 단독 실행하고, 나머지는 고정 크기 스레드 풀로 호출.
- HTTP/1.1, 요청마다 새 연결, keep-alive 없음. 루프백 C 서버, Python 표준 라이브러리.
- 지연시간은 클라이언트 연결·전송·응답 읽기 포함. 처리량은 전체 벽시계 기준.

repeat는 같은 상품 42, random100은 상품 100개에서 고정 난수 추출, unique는 요청마다 새 상품이다. 원본 횟수는 한 반복당 평균이며 원본 원장으로 확인한다.

반복 조회는 최초 원본 접근 이후 HTTP 캐시 조회만 수행한다. 새 키만 조회하면 적중이 없어 캐시 GET·PUT 네트워크 비용이 더해진다. 짧은 루프백 측정의 작은 차이는 스케줄링과 측정 변동을 포함하며 성능 향상을 보장하지 않는다. 원본 지연은 대기이므로 동시성에 따라 처리량이 달라진다. 동일 MISS의 몰림 방지는 구현하지 않았다.

매 요청 지연, 요청 순서, 반복별 통계와 환경은 [results.json](../bench/results.json)에 보존한다. 스크립트는 HTTP만 사용하며 저장소를 직접 링크하지 않는다.

재현: `make && python3 bench/compare.py --requests 60 --concurrency 4 --rounds 3 --delay-ms 300 --ttl-ms 60000`.

100만 회 엔진 마이크로벤치마크는 권장 선택 항목이며 이번 HTTP 캐시 비교에는 포함하지 않았다.
